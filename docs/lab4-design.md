## 讲义要求与项目约定的区别

来源：上级目录《【操作系统原理】实验讲义 1.doc》“四、进程调度”。本轮重新核对原文。

讲义要求在前三个实验基础上，连续调度全部进程，支持FCFS、SJF和时间片轮转；创建时输入到达/服务时间，适当展示队列变化及已执行/剩余时间，计算每进程的周转时间、带权周转时间和两个平均值；提供完成队列便于统计。

以下为本项目的设计安排，不冒充讲义固定实现方式：

- 使用逻辑时间，不sleep等待；尚未到达、就绪、运行、完成分别表示不同阶段，尚未到达不是阻塞。
- SJF采用上轮讲解的非抢占方式，按总服务时间burstTime选择，不做最短剩余时间抢占。
- 相同到达时间保留输入先后；SJF服务时间相同则选择原就绪队列中靠前的节点，不额外按名称排序。
- 用户在第六轮开始时已确认：RR先加入本片期间和片末的新到达者，再将未完成的运行者放回队尾。例如A在时刻2片满、B恰好在2到达，B排在回队的A之前；主循环及后续测试统一采用此规则。这是项目约定，不是讲义逐项规定。
- 模拟时钟及累计时间使用long long；非负到达时间、正服务时间、正RR时间片，以及时间累加上界由上层校验。队列只负责组织节点，不重复做业务输入检查。

## 类关系与数据归属

沿用已有简单结构，不新增一套与现有PCB、分页完全脱节的调度程序。

```text
实验四入口（后续接入，使用独立的ProcessManager实例）
  └─ ProcessManager：进程所有权、模拟时钟、算法选择、调度循环、时间统计
       ├─ PCBQueue：待到达 / 就绪 / 完成队列；running保存当前运行者
       ├─ PCB：身份、到达/服务/已执行/完成时间，以及已有分页信息
       └─ MemoryManager：沿用分页分配与回收接口，不决定谁先运行
```

原有手动进程/分页菜单保留，不把主菜单中已经运行的进程混进新建的自动模拟任务；文件系统不变。任务准备、清理、到达入队、运行者选择、执行推进、完成处理、空闲跳时、RR回队、公共调度循环、过程快照、周转统计及主菜单入口均已实现并验证。

一个PCB的next只能服务于一个链式队列，必须先从旧队列摘出，再进入新队列。PCB的创建/删除属于ProcessManager；队列不能擅自delete节点。

完成时应先回收分页资源，再保留PCB或结果到完成队列用于统计，不能照搬原terminateProcess立即delete的逻辑；最后退出/重置时统一清理。完成记录的时间字段不随内存回收而清空。

## 本轮PCB字段

保留原READY、RUNNING、BLOCKED的数值，追加NOT_ARRIVED、FINISHED。新字段仅供实验四，原手动模式仍按原逻辑运行；旧模式PCB默认burstTime=0不表示合法的自动调度任务。

| 字段 | 类型/默认值 | 职责 |
|---|---|---|
| arrivalTime | long long / 0 | 允许进入就绪队列的模拟时刻 |
| burstTime | long long / 0 | 总CPU服务时间；自动任务必须大于0 |
| executedTime | long long / 0 | 累计已执行时间；剩余量由burstTime减去它得到 |
| finishTime | long long / -1 | 完成时刻；-1表示还没有完成 |

周转时间=finishTime-arrivalTime；带权周转时间=周转时间/burstTime，必须浮点除法。平均值按实际完成进程数计算；零进程不能除以零。为避免相互矛盾，不再保存另一份“剩余时间”。

## 第一轮：用户实现两个队列方法

### void PCBQueue::pushByArrival(PCB* p)

- 原队列按arrivalTime非递减排列，传入未入队节点，返回void。
- nullptr不改变队列；实际插入后count加1。
- 相同到达时间插在已有同时间节点之后；正确维护head、tail和next。
- 不分配、删除PCB，不推进时间，不改变状态或其他时间字段。
- 上层负责非负时间与节点所有权；不能将同一个PCB重复插入或同时插入不同队列。

### PCB* PCBQueue::popShortest()

- 空队列返回nullptr，其他状态不变。
- 取出burstTime最小的节点；并列时保留原队列中的先后。
- 只摘链，其他节点相对顺序不变；更新head、tail、count，被取出节点next为空。
- 不delete节点、不改变状态/时间/分页数据；调度器以后再把返回节点设置为RUNNING。

框架准备时pcb_queue.cpp只放置任务块和边界提示，没有提供函数实现；用户随后自行完成两个定义，首次运行复查结果见文末。现有菜单暂未调用这两个方法，因此主程序能运行不代表新方法正确。

### 新增成员

- pending：按到达时间排列，节点状态NOT_ARRIVED，已经分配分页资源。
- finished：完成记录队列；后续进程完成时先回收资源，再进入该队列，不在退出时重复回收。
- currentTime：long long，默认0，记录本批模拟时钟。
- schedulingStarted：bool，默认false；后续开始运行时置true，防止中途追加任务改变本批输入。

时钟和标志使用成员默认初值；两个新队列沿用原PCBQueue构造函数。原ProcessManager构造函数和手动菜单无需因此改变。

### 任务1：扩展void ProcessManager::clearProcesses()

保留原running/ready/blocked清理，再清理pending、finished：pending先释放分页资源再摘链/delete，finished只摘链/delete。最后currentTime=0、schedulingStarted=false，nextPid不重置。用于本管理器合法拥有的进程，不引入损坏页表修复或重复释放机制。

### 任务2：bool ProcessManager::createScheduledProcess(...)

```cpp
bool createScheduledProcess(const string& name,int sizeBytes,

```

- name沿用现有string名称规则，不新增长度/重名约束；sizeBytes>0、arrivalTime>=0、burstTime>0。residentPages沿用原MemoryManager规则，默认-1。
- 仅允许准备阶段：schedulingStarted为false、running为空、ready/blocked/finished为空；pending可以已有条目，才能逐个准备一批任务。

### bool ProcessManager::advanceRunning(long long duration)

- duration表示本次实际执行时长，而非绝对目标时刻，必须大于0且不超过剩余服务量；超过时拒绝，不自动截短。这是项目内部接口约定，不是讲义指定的函数形式。
- 要求running非空且状态RUNNING，burstTime>0，0<=executedTime<=burstTime，finishTime=-1；时钟及到达时间非负，到达时间不晚于时钟。
- 先验证字段，再计算burstTime-executedTime；在加法之前用long long上界减currentTime来检查duration，避免先溢出再判断。已执行时间的增加受剩余量限制，不会超过已验证的burstTime。
- 所有检查通过后，才同时给currentTime和executedTime增加duration，返回true；任何失败均返回false，两个时间及其他状态不变。
- 不改状态、其他CPU时间、队列、PID、开始标志或分页资源；不自动收取到达者、不处理完成/回队/统计。执行量恰好耗尽后仍保留running，交给另一个方法完成。

### bool ProcessManager::finishRunningProcess()

- 无参数；只有running状态RUNNING、正服务时间且executedTime恰好等于burstTime、尚无完成时刻，以及合法非负时钟/到达关系时才可完成。
- 必须先调用并确认memory.release成功，再记录finishTime=currentTime、设置FINISHED、将原PCB追加finished并清空running，最后返回true。
- 资源释放失败立即返回false，保留原运行者、状态和完成时间，不把失败节点放入finished。当前MemoryManager先完整校验再释放，false时没有部分清空。
- 不delete PCB，不调用旧terminateProcess或dispatch；不推进时钟、不更改已执行时间、PID和开始标志。连续调用第二次因running已空而拒绝，不能重复追加记录。

### bool ProcessManager::jumpToNextArrival()

- 无参数；只有running为空、ready为空、pending非空、currentTime>=0，且pending队头到达时间严格晚于当前时钟时才成功。

### bool ProcessManager::requeueRunning()

- 无参数；要求运行者非空且状态RUNNING，burstTime>0、0<=executedTime<burstTime、finishTime=-1，时钟和到达时间非负且已到达。

- 只回队，保留身份、时间、分页资源和统计，不执行、不完成、不释放、不删除、不收取到达者、不立即选下一个运行者。ready原来为空也可成功回队。
- 主循环决定何时用完时间片及是否调用本方法；本方法不能从累计执行量推断本片执行了多少。0执行量仍符合未完成字段条件，但正常RR调用顺序是先推进本片，再回队。
- 例：A服务5、已执行2，ready原为B、C；回队后B、C、A，CPU空闲。旧timeOut同时回队和立即选人，不能替代本方法。
