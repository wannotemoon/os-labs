## 第一轮用户实现任务

新建disk.cpp并包含disk.h，本轮只实现以下两个方法：

1. `DiskManager::DiskManager(int blockCount)`
   - 检查块数是8至1024之间的2的幂，非法时抛出std::invalid_argument；与现有Bitmap构造检查风格一致。
   - 保存块数，准备同样数量的16位FAT表项，先置为空闲，再保留0号根目录块为LAST_BLOCK。

2. `int DiskManager::getFreeBlockCount() const`
   - 只统计FAT缓存中等于EMPTY_BLOCK的表项，不能仅返回blockCount-1，也不能改变FAT。

当前缓存是待保存的磁盘初始状态；未open时的统计不表示已经在电脑上创建了虚盘。

## 先理解三个概念

虚盘文件：电脑上的一个普通二进制文件。我们在它的内部模拟磁盘，不把命令直接交给 Windows。

FCB：一个文件或子目录的目录项。记录它叫什么、是什么类型、何时创建、多大、首个磁盘块在哪里。
目录本身占磁盘块，块内存放它的子项 FCB；由这些引用形成目录树。

FAT：按磁盘块号索引的表。一个表项表示该块空闲、已是链尾，或者下一个块的块号。
例如文件的 firstBlock 为2，FAT[2]为5，FAT[5]为LAST_BLOCK，说明它占用2号和5号两个块。
FCB 找到链首，FAT 连接后续块，虚盘文件中对应的数据区保存实际块内容。

## 类关系与数据归属

```text
main / 文件系统命令入口
  ├─ ProcessManager → MemoryManager → Bitmap       已有实验一、二
  └─ FileSystem → DiskManager → 虚盘文件             实验三
       │              │
       │              └─ 文件流、FAT缓存、磁盘块读写和分配回收
       └─ 当前路径、目录项解释、目录树操作和命令语义
```

FCB 是普通数据结构，不负责读写文件，不新增一套节点管理器。
FileSystem 持有一个 DiskManager；DiskManager 持有文件流和 FAT 数组缓存。
FAT 缓存与虚盘中的 FAT 对应，成功修改后同步；块空闲情况由 FAT 判断，不再另外维护 Bitmap。

目录树保存在虚盘的目录项中，不另建一棵长期驻留内存、需要重复同步的 child/next 树。
FileSystem 仅保存当前导航路径（目录名和首块号组成的路径栈）；目录项按需读取。
FCB 是目录项；PCB 是进程控制块，二者职责不同，不给 PCB 加文件系统字段。
文件系统磁盘块也不占用实验二的物理页框或置换块。

主菜单后续新增文件系统入口，进入后使用命令行，返回时仍可操作原来的进程、分页功能。
暂不改动现有 ProcessManager、MemoryManager、PCBQueue 的接口。

## 磁盘布局与数据表示

- 默认64个数据块，每块1024字节；构造参数支持8至1024之间的2的幂，便于复现讲义8块案例。
- FAT16：每项2字节，64项共128字节。布局为 `[FAT | 64个数据块]`，总文件长度65664字节。
- 数据块号从0开始；0号块固定给根目录，永不分配给其他文件，也不允许删除根目录。
- EMPTY_BLOCK 为0x0000，LAST_BLOCK为0xFFFF，沿用讲义。根块固定保留后，普通文件链不需要指向0号块，避免与空闲标记混淆。
- 新目录起初分配1个块；目录项满时的FAT目录链扩展预留接口，后续分轮实现。普通文件按字节数向上取整分配数据块。
- 磁盘目录项固定32字节：名称8、大小4、首块号4、类型1、创建时间15。
- 内存中的 FCB 可使用 string 和 int；磁盘格式显式编码/解码，不能把含 string 的 C++ 对象直接写盘，也不依赖 sizeof(FCB)。
- 名称字段最多8个UTF-8字节，不等于8个中文字符；日期字段为15个ASCII字节，格式 `yyyymmdd hhmmss`，不附加终止符。
- 类型0表示未使用或已删除，1表示文件，2表示目录。DIR 将日期、时间转换成讲义示例的可读格式。
- 文件大小为逻辑字节数；目录大小为实际已分配的目录空间字节数，初始为1024。空文件允许大小0、首块号-1，不占数据块。
- 数据块读写偏移为FAT字节数加块号乘1024；块号不直接当成文件字节偏移。
- 若虚盘不存在则创建；若存在则打开并核对布局，不能每次启动自动格式化，更不能因文件不合法而覆盖它。
- 虚盘、临时文件与构建产物不提交Git；正式加入虚盘路径时同步增加准确的忽略规则。

上述容量、名称限制和空文件规则属于已确认的项目约定，不冒充讲义明确规定；命令解析的未定细节仍单独讨论。

## 接口约定

以下公共接口已在disk.h和file_system.h声明；两个类均通过构造参数设置块数，默认64。
fcb.h只定义目录项数据，不定义文件系统算法。
bool方法成功返回true；失败返回false，并可通过 `getLastError()` 获取最近一次失败原因。
业务错误由命令入口打印一次，底层磁盘操作不直接输出“创建成功”等提示。

DiskManager 只处理磁盘和块，不理解MD、CD或文件名：

| 接口 | 职责与边界 |
|---|---|
| `bool openDisk(const string& path)` | 打开已有虚盘，或在不存在时创建新虚盘；失败不覆盖已有文件 |
| `bool readBlock(int blockNo, vector<char>& buffer)` | 读一个完整块；成功输出1024字节，拒绝越界块号 |
| `bool writeBlock(int blockNo, const vector<char>& buffer)` | 写一个完整块；只接受1024字节缓冲区，检查写入结果 |
| `bool showInfo(int byteOffset, int byteCount = 256)` | 只读查看虚盘文件原始字节，包含FAT和数据区；按图4-7显示偏移、十六进制和可打印ASCII |
| `bool allocateBlocks(int count, int& firstBlock)` | 分配并连接若干空闲块；count须为正，空间不足不残留部分分配 |
| `bool getChain(int firstBlock, vector<int>& blocks)` | 按顺序取得块链，检查越界、空闲链和循环链；失败记录原因 |
| `bool extendChain(int firstBlock, int count)` | 给已有链追加块，用于目录扩展；空间不足不改变原链 |
| `bool freeChain(int firstBlock)` | 回收合法块链；先核对整条链，不释放根目录块；空链规则单独处理 |
| `int getFreeBlockCount() const` | 由FAT统计空闲块，不修改磁盘 |
| `void showFat() const` | 辅助验收，查看空闲标记、块链接和链尾 |
| `const string& getLastError() const` | 获取磁盘操作失败原因 |

FileSystem 按目录项组织文件系统，磁盘读写交给DiskManager：

| 接口 | 职责与边界 |
|---|---|
| `bool open(const string& diskPath)` | 初始化虚盘和根目录导航状态；新旧虚盘分别处理 |
| `bool makeDirectory(const string& name)` | 当前目录下创建空目录；检查名称、重名和空间 |
| `bool changeDirectory(const string& target)` | 切换到合法目录；失败不改变当前路径 |
| `bool removeDirectory(const string& name)` | 只删当前目录中的空子目录；拒绝文件、根、`.`和`..` |
| `bool makeFile(const string& name, int sizeBytes)` | 创建指定字节大小的文件；检查负数、重名和空间，按需分配块 |
| `bool deleteFile(const string& name)` | 只删除普通文件并回收全部块，不把目录当文件删除 |
| `bool listDirectory()` | 按图4-1输出当前目录，读盘失败返回false |
| `bool showDiskInfo(int byteOffset, int byteCount = 256)` | 将info请求交给DiskManager，传播失败原因，不修改文件系统 |
| `string getCurrentPath() const` | 返回带根和尾部分隔符的路径，例如 `\test\` |
| `const string& getLastError() const` | 获取业务或下层I/O失败原因 |

当前声明少量直接的辅助方法：创建虚盘、FAT读写、目录项读写、名称校验、生成时间字符串。
readEntry/writeEntry使用块号和块内0至31号槽位定位一个32字节目录项；不按C++对象大小定位。
后续实现需要的查找辅助方法按具体需要补充，避免提前设计大量封装。
FileSystem负责FCB的磁盘编解码；DiskManager只读写原始块和FAT。

命令入口逐行读取，解析关键字和参数；只转换命令关键字的大小写，不擅自改变文件名。
拟支持 `MD name`、`CD name`、`CD ..`、`CD \`、`RD name`、`MK name sizeBytes`、`DEL name`、`DIR`、`info byteOffset`。
文件名大小写是否区分、是否支持多级路径、空格名称以及退出命令，需要在写解析器前确认。
info是讲义建议项，应纳入外存方案；独立的FAT/空间解读入口是项目额外的辅助设想，不替代info。
不给六个命令额外打印成功信息。

### 严格沿用讲义的8块案例

以下把FAT放在文件开头，后接数据块，使用讲义给出的FAT16和块大小：

```text
虚盘文件
  FAT：8项 × 2字节 = 16字节
  数据区：8块 × 1024字节 = 8192字节
  整个文件：8208字节

文件偏移 0..15       FAT
文件偏移 16..1039    数据块0（根目录）
文件偏移 1040..2063  数据块1
文件偏移 2064..3087  数据块2
文件偏移 3088..4111  数据块3
```

这里的块号和整个虚盘文件的字节偏移不是同一件事。
FAT位于数据区之前，所以8块案例中，0号数据块从文件偏移16开始。

| 案例阶段 | FAT[0] | FAT[1] | FAT[2] | FAT[3] | FAT[4..7] |
|---|---|---|---|---|---|
| 建立空虚盘，尚未分配根目录 | 0000 | 0000 | 0000 | 0000 | 全部0000 |
| 根目录占0号块 | FFFF | 0000 | 0000 | 0000 | 全部0000 |
| 根目录下MD test，test占1号块 | FFFF | FFFF | 0000 | 0000 | 全部0000 |
| 在根目录MK a.c 2000，占2、3号块 | FFFF | FFFF | 0003 | FFFF | 全部0000 |
| 在根目录RD test，回收1号块 | FFFF | 0000 | 0003 | FFFF | 全部0000 |

表中FAT值用十六进制表示；0000为空闲，FFFF为链尾，0003为下一块是3号块。

建立根目录：0号块作为根目录的数据区域，起初没有用户创建的子项。
根目录需要一个入口，由FileSystem初始化导航状态时固定指向0号块，不需要在根目录里再保存它自己的FCB。

创建test：DiskManager分配1号块作为test的目录数据块；FileSystem在根目录的0号块中写入test的FCB。
test的FCB保存名称test、目录类型、创建时间、首块号1。
讲义外存示例将test大小写为1024；上一稿建议目录大小记0是项目自定规则，尚未确认。
为了与外存示例逐项一致，可以采用目录大小记录已分配目录空间字节数；若目录随后扩展，还需同步更新其父目录中的FCB。

创建a.c：根目录再保存一个FCB，名称a.c、文件类型、大小2000、首块号2。
2000字节需要2个1024字节块；FAT[2]=3、FAT[3]=FFFF。
逻辑上文件占2000字节，实际分配2048字节，最后48字节不属于文件逻辑内容。
讲义没有给a.c的具体内容；此阶段只验证创建、分配和目录信息，不把内容编辑作为必做命令。

删除test：RD首先检查它是空目录，再回收1号块，并把根目录中test项的类型置0。
这对应讲义第（5）项。原目录项的其他字节不要求都清零，但DIR不得显示已删除项。
info是原始字节查看，可能仍能看到已删除项的旧名称；类型0表示该项已经失效。

补充演示DEL a.c：这是对讲义必做DEL命令的补充演示，不是讲义已有案例步骤。
回收2、3号块，根目录中的a.c项置为类型0；只保留根目录占0号块。
不能只释放首块而遗留后续块，也不能把根目录块一并回收。

### info的明确职责与边界

`info 0`：从整个虚盘文件偏移0开始，默认显示256字节，即偏移0至255。
不是从第0号数据块开始，也不是只显示第0个文件。
8块案例中，这256字节包含16字节FAT和根目录块的前240字节。

拟按图4-7每行显示16字节：左边为整文件绝对字节偏移，中间为两位十六进制字节，右边显示可打印ASCII，其他字节用点表示。
中文名称的UTF-8字节仍在中间完整显示；右侧ASCII栏不负责解码中文。
截图中的具体字节与其磁盘配置、目录项格式和创建时间有关，不能要求我们的每个字节都与截图相同。

查看FAT表项值与查看文件字节要分开：例如FAT[2]=0x0003是一个16位数，若采用小端编码，在info里是`03 00`。
讲义没有明确约定字节序，本项目建议统一小端；0xFFFF在info里显示为`FF FF`。
showFat则可以直接输出“2号块 -> 3号块”等解释性内容，它不能替代info。

参数与边界草案：

- 命令基本形式沿用讲义`info offset`，关键字大小写同样可识别。
- 偏移按十进制字节数输入，非数字、负数或超出文件范围时提示错误。
- 靠近文件末尾时只显示实际剩余字节，不越界、不补造不存在的字节。
- 只读，不改变FAT、目录项、当前目录和分配状态；输出后后续读写仍应正常。
- 接口保留byteCount默认值256便于测试；是否向用户开放`info offset count`扩展语法尚未决定，讲义未要求它。
- info定位在DiskManager，因为它查看的是整个虚盘文件的原始字节；FileSystem只提供命令转发和错误传播。

确认接口后，计划在虚盘打开与块读写阶段尽早加入info，方便后续每个方法都能看到真实磁盘变化。
